# M3 — Multi-workspace + Onboarding

Exit criteria: feature 4 + onboarding (PLANO v2 §3.7): create workspaces from folders,
tabs switch board+terminals without rebuild, per-workspace tmux session, `dev_workspace()`
hardcode deleted.

---

## M3-T1 — Workspace creation + remote parsing
**Refs:** CONTRACTS §7 (`workspace_create`, `workspace_list`), §9.1/§9.2 (slug, remote
vectors), §3 (session naming).
**Files:** `ipc/workspace.rs`, `gitlocal.rs`, `models.rs`.
**Steps:** `workspace_create(path)`: validate dir exists; slug = `slugify(dirname,
"ws-<uuid8>")`, suffix `-2`, `-3`… on UNIQUE collision; detect repo via
`git2::Repository::discover` strictly inside `path`; if remote `origin` exists, parse via
§9.2 → set owner/repo or notify `REMOTE_NOT_GITHUB` and stay local. Seed 5 columns. No
token prompt here (M5-T1).
**DoD:** §9.2 vector tests; tests: non-git folder → local workspace; slug collision gets
suffix. Gates green.
**Out of scope:** token flow, sync start.

## M3-T2 — Workspace tabs + per-workspace board
**Refs:** CONTRACTS §17.
**Files:** `components/Tabs.tsx`, `store/workspaces.ts`, `store/board.ts` (keyed by
workspace), `App.tsx`.
**Steps:** tab bar listing workspaces + "+" tab. Active workspace id in `ui_state`
(`active_workspace`). Switching tabs calls `board_get` for the target (cache it; `evt:board`
keeps caches fresh by workspace_id). Board renders the active workspace only.
**DoD:** manual: 2 workspaces, cards isolated per board, restart restores active tab.
vitest: board store keeps per-workspace card maps separate.
**Out of scope:** terminal handling (next task), drag between workspaces (not a feature).

## M3-T3 — Per-workspace terminals + lazy mount
**Refs:** CONTRACTS §8 (session per slug), §10 (dispose rules).
**Files:** `store/terminals.ts`, `components/TerminalPane.tsx`, `ipc/terminal.rs`
(replace `dev_workspace()` with real workspace lookup — delete the hardcode).
**Steps:** terminals belong to a workspace (`store` keyed by workspace_id, each entry
keeps `{window_id, pane_id?}`). Inactive workspace ⇒ unmount TerminalPane components
(dispose addon + `terminal_close`, which kills only the viewer — the tmux window
survives) but keep `window_id`s in `ui_state` (`terminals:<workspace_id>` →
`[window_ids]`). Activating a workspace ⇒ for each saved window id, if alive (§8)
reattach via `terminal_open(workspace_id, window_id)`; drop dead ids.
**DoD:** manual: ws A runs `top`, switch to B, back to A → `top` still running, no
duplicate windows. Restart app → A's terminals reattach. `[needs-tmux]` test for
"reattach to existing window does not run startup command".
**Out of scope:** feature-6 trigger, pane split layouts.

## M3-T4 — Onboarding UI
**Refs:** PLANO v2 §3.7; CONTRACTS §7.
**Files:** `components/Onboarding.tsx`, `App.tsx`, `lib/ipc.ts`.
**Steps:** when `workspace_list` is empty: centered empty state with one primary button
"Open a folder…" → `@tauri-apps/plugin-dialog` `open({directory: true})` →
`workspace_create`. Show resulting workspace name + linked repo (or "local only") line.
The same button lives behind the "+" tab afterwards.
**DoD:** manual: fresh DB → onboarding → pick a git folder with GitHub origin → tab
appears, owner/repo stored; pick a plain folder → local workspace, `REMOTE_NOT_GITHUB`
toast NOT shown (only shown when origin exists but isn't GitHub).
**Out of scope:** token entry (M5-T1 adds it to settings + a prompt on first linked
workspace), workspace deletion UI (post-v1; `workspace_delete` not in scope).
