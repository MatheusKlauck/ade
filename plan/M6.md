# M6 — Settings, notifications & polish

Exit criteria: theme setting works; notification history; performance pass done; signed,
notarized, auto-updating `.app`. v0.1 tag.

---

## M6-T1 — Settings screen (theme first)
**Refs:** CONTRACTS §17 (CSS vars), §7 (settings commands), PLANO v2 §3.8.
**Files:** `components/Settings.tsx`, `index.css`, existing token field moves here.
**Steps:** modal/page with: theme (light/dark) + accent color (input type=color →
`--accent`), global startup command, sync interval (seconds, min 10), GitHub token
(masked, "Replace" button). Apply theme by setting `data-theme` on `<html>` at startup
from `setting theme`.
**DoD:** manual: toggle theme persists across restart; interval change visibly affects
worker (log line). vitest: settings store maps defaults.
**Out of scope:** terminal font setting, per-workspace startup UI (post-v1).

## M6-T2 — Notification center
**Refs:** CONTRACTS §7 (codes — exhaustive), PLANO v2 §3.9.
**Files:** `components/NotificationCenter.tsx`, `store/notifications.ts`.
**Steps:** bell icon with unread badge; panel lists history (level icon, code, message,
relative time), "Clear". History capped at 200 in memory; persists nothing (by design —
DECISIONS if you disagree).
**DoD:** manual sweep: trigger at least `TMUX_TOO_OLD` (fake the version string in a dev
build), `TOKEN_INVALID`, `INTENT_DROPPED` (via spike scenario or manual), each appears in
history. vitest: store caps at 200.
**Out of scope:** OS-native notifications.

## M6-T3 — Performance pass
**Refs:** PLANO v2 §5; CONTRACTS §10, §15.
**Files:** whatever the findings require (each fix = separate commit referencing this task).
**Steps:** checklist, record numbers in PROGRESS.md:
1. Cold start to interactive < 1 s (manual stopwatch, release build).
2. `EXPLAIN QUERY PLAN` on the board query uses `idx_card_board`.
3. Re-run the M1-T6 `cat` benchmark in release.
4. Switching between 2 workspaces with 4 terminals: no console errors, no leaked
   `Terminal` instances (heap snapshot count stable across 5 switches).
5. Board with 600 cards (script-insert) drags smoothly; if not, virtualize is **not**
   allowed (no new deps) — cap rendered cards per column at 100 with "show more" and a
   DECISIONS note.
**DoD:** all five recorded; regressions fixed.

## M6-T4 — Package, sign, notarize, auto-update
**Refs:** Tauri v2 distribution docs (bundler, updater plugin), PLANO v2 §6.
**Files:** `src-tauri/tauri.conf.json`, CI-less local scripts `scripts/release.sh`.
**Steps:** configure bundle identifier, icons (placeholder set ok), updater plugin
(`tauri-plugin-updater` — allowed addition, it's part of distribution; add to §1 + lockfile
+ DECISIONS) pointing at a GitHub Releases JSON; document signing/notarization env vars
(`APPLE_ID` etc.) in `scripts/release.md` for the human to run — do NOT attempt
notarization yourself.
**DoD:** `npm run tauri build` produces a `.app`/`.dmg` locally; release.md is complete
enough for the human to sign+notarize.
**Out of scope:** CI pipelines.
