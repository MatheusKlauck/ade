# M4 — Auto-launch (feature 6)

Exit criteria: user-drag into Doing opens (or focuses) a tmux window for the card, with
env/branch for linked cards, per CONTRACTS §16 — all three variants work: linked, local,
re-entry. Sync-driven moves never trigger anything.

---

## M4-T1 — Branch logic
**Refs:** CONTRACTS §16 step 2, §3 (branch name), §7 (codes BRANCH_*).
**Files:** `gitlocal.rs`.
**Steps:** `prepare_branch(repo_path, issue_number) -> Result<BranchOutcome>` where
`BranchOutcome ∈ {Created, ReusedExisting, SkippedDirty}`. Rules: worktree dirty
(`statuses` non-empty, ignoring untracked? **No** — untracked counts as clean; modified/
staged counts as dirty) ⇒ `SkippedDirty` without touching anything; branch `issue-<n>`
exists ⇒ checkout, `ReusedExisting`; else create from HEAD + checkout, `Created`.
**DoD:** tests on `tempfile` repos (init with git2, one commit): clean→Created;
re-run→ReusedExisting; dirty file→SkippedDirty and branch unchanged.
**Out of scope:** push, branch name patterns (v1 is fixed `issue-<n>`).

## M4-T2 — Trigger wiring in card_move
**Refs:** CONTRACTS §16 (all rules), §8 (issue window row), §9.1 (window name vectors).
**Files:** `ipc/board.rs` (the `// M4` marker from M2-T2), `tmux.rs` (issue window fn),
`sync/worker.rs` guard check.
**Steps:** implement §16 steps 1–5 exactly. Map `BranchOutcome` → notifications
(`BRANCH_EXISTS_REUSED` info, `BRANCH_DIRTY_WORKTREE` warn). Store `terminal_window_id`.
Confirm by reading the code (and assert in a test) that the sync path uses the internal
move function and **cannot** reach this trigger.
**DoD:** Rust test: internal sync move into Doing does not call tmux (inject a tmux trait
or a call-recording stub for tmux.rs functions — smallest possible seam, note in
DECISIONS). `[needs-tmux]` test: linked-card trigger creates window with name `<n>-<slug>`
and env `ISSUE_NUMBER` visible via `tmux show-environment -t <win>`. Injection vector:
issue title `$(touch /tmp/pwned)` → window created, `/tmp/pwned` does NOT exist.
**Out of scope:** outbox enqueue on the move (M5-T4 adds it for linked cards).

## M4-T3 — Frontend focus + variant UX
**Refs:** CONTRACTS §7 (`evt:terminal_focus`), §17.
**Files:** `store/terminals.ts`, `components/TerminalPane.tsx`, `components/Board.tsx`.
**Steps:** on `evt:terminal_focus`: ensure a pane exists for that window (reattach if
needed), switch UI focus to it (scroll into view + visual highlight 1 s). Local cards in
Doing get the same flow (no env/branch — that's already the Rust side's concern).
**DoD:** manual checklist: (a) linked card → Doing: window `#N-...` focused, branch
created; (b) same card Doing→Paused→Doing: same window focused, no duplicate; (c) local
card → Doing: window opens named from title; (d) dirty worktree: terminal opens, warn
toast, branch untouched.
**Out of scope:** closing windows when cards leave Doing (explicitly NOT a feature —
§16.5).
