# M1 — Terminal (nested tmux attach)

Exit criteria: open/close fast terminals attached to a per-workspace tmux session; close
the app, reopen, reattach and everything is still there; heavy output doesn't drop frames
(manual benchmark); startup command runs in new windows. Features 3 + 5.

> M1 works against a hardcoded dev workspace (slug `dev`, root = a folder you create in
> `$TMPDIR`) — real workspaces arrive in M3. Put the hardcode in ONE place behind
> `fn dev_workspace()` so M3 deletes it cleanly.

---

## M1-T1 — tmux module
**Refs:** CONTRACTS §8 (the whole table), §6 (Tmux errors).
**Files:** `tmux.rs`.
**Steps:** implement every row of §8 as a function taking/returning plain strings, all via
`std::process::Command` argv arrays. `check_version()` parses `tmux -V` (accept formats
`tmux 3.4`, `tmux 3.3a`, `tmux next-3.5`); `>= 3.2` required. All stderr text goes into
`AdeError::Tmux`.
**DoD:** unit tests for version parsing (vectors: `tmux 3.2`✓, `tmux 3.1c`✗, `tmux 2.9`✗,
`tmux next-3.6`✓, garbage✗). `[needs-tmux]` ignored test: ensure base → new window →
window alive → kill window, asserting real ids.
**Out of scope:** PTY, IPC, send-keys content rules.

## M1-T2 — PTY pipeline
**Refs:** CONTRACTS §10 (copy the snippet).
**Files:** `pty.rs`.
**Steps:** `PtyPane { id, writer, master, child }` registry in a `Mutex<HashMap>` inside
tauri State. Spawn per §10 with the §8 viewer-attach argv. Implement `write`, `resize`
(`master.resize(PtySize{..})`), `close` (kill child, drop pair, then §8 kill-viewer).
Reader thread sends raw bytes into the Channel; on EOF send nothing and remove from
registry.
**DoD:** `[needs-tmux]` ignored test: spawn a pane against a real tmux, write
`echo hi\r`, read until output contains `hi` (with timeout), close cleanly.
**Out of scope:** frontend; startup command.

## M1-T3 — Terminal IPC commands
**Refs:** CONTRACTS §7 (terminal_*), §8 (open flow), §10 (Channel arg).
**Files:** `ipc/terminal.rs`, `main.rs` (register), `lib/ipc.ts`.
**Steps:** `terminal_open(workspace_id, window_id?, channel)`: version gate → ensure base
session → if no `window_id`, create app window (§8) **and run startup command** (M1-T5
does the command lookup; for now inject literal `""` = skip) → spawn viewer pinned to the
window → `set-option status off` → return `{pane_id, window_id}`. Wire write/resize/close.
**DoD:** manual: from devtools, `terminal_open` + a raw `console.log` of first bytes works.
Gates green.
**Out of scope:** React component.

## M1-T4 — Terminal React component
**Refs:** CONTRACTS §10 (frontend half), §17.
**Files:** `components/TerminalPane.tsx`, `store/terminals.ts`, `lib/ipc.ts`, `App.tsx`
(temporary button "New terminal" on the dev workspace).
**Steps:** exactly as §10: Channel onmessage → rAF-batched `term.write`; WebGL addon in
try/catch with canvas fallback; FitAddon + ResizeObserver → `terminal_resize`; onData →
`terminal_write`; unmount disposes WebGL addon first, then terminal, then
`terminal_close`. Multiple panes side by side (simple flex grid; no fancy layout).
**DoD:** manual checklist in `plan/PROGRESS.md` M1 section: open 2 panes, run `top` in
one, resize window, close pane, no console errors.
**Out of scope:** workspace tabs, persistence of layout.

## M1-T5 — Startup command injection
**Refs:** CONTRACTS §8 (send-keys row), §7 (settings).
**Files:** `ipc/terminal.rs` (small change), `tmux.rs` (send_keys fn if missing).
**Steps:** on **new window creation only** (not reattach): command =
`workspace.startup_command` else `setting startup_command_global`; if non-empty,
`send-keys -t <window_id> <cmd> Enter`. The command is user-authored (trusted) but is
still passed as ONE argv element.
**DoD:** `[needs-tmux]` test: create window with startup `export ADE_TEST=1`, then
send-keys `echo $ADE_TEST` and capture-pane shows `1`. Manual: set global startup to
`clear && echo ready`, new pane shows `ready`.
**Out of scope:** per-workspace settings UI.

## M1-T6 — Persistence + performance acceptance
**Refs:** PLANO-ADE-v2 §5 goal; CONTRACTS §10.
**Files:** `plan/PROGRESS.md` (record results), no production code unless fixing findings.
**Steps:** Manual protocol, record outcomes:
1. Open 2 panes, run `watch date` in one. Quit app. Reopen, `terminal_open` with the
   stored window ids (hardcode for the test) → both sessions intact.
2. Benchmark: `base64 < /dev/urandom | head -c 100000000 > /tmp/big.txt` then `cat
   /tmp/big.txt` in a pane. UI must stay responsive (can move mouse, click) and finish
   without the renderer freezing. If it freezes: verify rAF batching and chunk size, fix,
   re-run.
**DoD:** both protocol results written into PROGRESS.md. Any fix committed separately.
**Out of scope:** control-mode, automated FPS measurement.
