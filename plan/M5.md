# M5 — GitHub bidirectional (feature 2)

Exit criteria: PAT auth; seed + incremental sync drive the board; user moves write back
via labels through the outbox; promote local→issue; linked card detail; the M2-T8 spike
suite still green and extended. All HTTP tested via wiremock; live GitHub only in the
final manual checklist.

---

## M5-T1 — Token validation + settings entry
**Refs:** CONTRACTS §7 (`github_set_token`), §11 (GET /user), §6.
**Files:** `ipc/github.rs`, `gh/client.rs`, minimal settings modal (gear icon → token
field + "Save"), `components/Onboarding.tsx` (prompt when creating a linked workspace and
no token stored).
**Steps:** `github_set_token`: call GET /user with the token; 401 ⇒ `TokenInvalid` (do
NOT store); success ⇒ store in Keychain, return login. 403 with scope-ish message ⇒
notify `TOKEN_SCOPE`.
**DoD:** wiremock tests: valid→stored(mock keychain seam), 401→error & not stored.
Manual: bad token shows toast.
**Out of scope:** Device Flow, multiple accounts.

## M5-T2 — Ensure labels + write operations
**Refs:** CONTRACTS §11 (ensure labels, add/remove label, close/reopen), §3 (colors).
**Files:** `gh/client.rs`.
**Steps:** `ensure_labels(owner, repo)` (422 ⇒ ok), `add_label`, `remove_label`
(404 ⇒ ok), `set_issue_state`. All take the injectable base URL.
**DoD:** wiremock tests incl. the 422 and 404 tolerance cases.
**Out of scope:** mapping intents → calls (next task).

## M5-T3 — Sync worker + rate budget
**Refs:** CONTRACTS §14 (verbatim), §12, §11.
**Files:** `sync/worker.rs` (promote `run_cycle` from M2-T8 to a scheduled task),
`main.rs` (spawn on startup per linked workspace; respawn on workspace_create).
**Steps:** implement §14: interval from settings; seed when `last_sync IS NULL`
(`ISSUE_LIST_LARGE` over 500); `ensure_labels` once per workspace (flag `labels_ensured` in
`sync_state` — add via a **new** migration file `migrations/0003_sync_labels_flag.sql`;
never edit the already-applied `0002` from M2-T6 (checksum mismatch breaks startup);
DECISIONS note); RateBudget global; `evt:sync` transitions; `sync_now` command kicks the
task (use a `tokio::sync::Notify`).
**DoD:** integration test (temp DB + wiremock): two cycles — seed then incremental with
`since` asserted on the second request. RateBudget test: after a 403, subsequent calls
short-circuit until `paused_until`.
**Out of scope:** UI beyond `evt:sync` emission.

## M5-T5 — Promote local card ("Create GitHub issue")
**Refs:** CONTRACTS §7 (`card_promote`), §11 (create issue).
**Files:** `ipc/board.rs`, `gh/client.rs`, `components/CardDetail.tsx` (button).
**Steps:** POST issue with title+body; on success set `source=github`,
`github_issue_number`, `github_state=open`, `remote_updated_at` from response. **If the
card's column ≠ Backlog, call `add_label` (§11) for that column's `kanban:*` label and
set `remote_updated_at` from that response (or re-fetch the issue) — without this the
new issue carries no kanban label and the first incremental poll moves the card to
Backlog via §12 row 7.** Emit `evt:board`. Button label: **"Create GitHub issue"** —
visible only on local cards in linked workspaces. Synchronous: button shows spinner,
error ⇒ toast, card stays local.
**DoD:** wiremock tests: happy path (Backlog card → POST issue only); promote of a
**Doing** card issues both the POST and the `add_label kanban:doing` call (assert
wiremock received both); 403 path leaves the card local. Manual on live repo (checklist).
**Out of scope:** editing the issue body afterwards (post-v1: local edits to linked cards
don't write back except column moves — note this in the detail panel UI as read-only
fields for linked cards).

## M5-T6 — Linked card detail
**Refs:** CONTRACTS §7 (`card_detail`), §11 (full issue + comments).
**Files:** `ipc/board.rs`, `gh/client.rs`, `components/CardDetail.tsx`.
**Steps:** for `source=github`: fetch issue + first 30 comments on open (loading state;
error ⇒ toast + fallback to cached row fields). Render body as plain text (**no**
markdown rendering lib — not in §1), labels as chips, assignee, link "Open on GitHub"
(opens browser via tauri opener — if a plugin is needed and not in §1, render the URL as
copyable text instead; DECISIONS note).
**DoD:** wiremock test for fetch mapping. Manual: double-click linked card shows body
and comments.
**Out of scope:** writing comments, editing remote fields.

## M5-T7 — Live acceptance checklist (manual, real repo)
**Files:** `plan/PROGRESS.md` (record each item).
**Steps:** on a scratch repo you own: token setup → workspace link → seed pulls open
issues (PRs absent) → labels `kanban:*` exist → drag Backlog→Doing puts label →
Done closes issue → reopen on GitHub moves card out of Done on next poll → close on
GitHub while card in Doing moves it to Done → promote a local card → detail panel.
**DoD:** every item checked with result noted. Failures become bugfix commits before M6.
